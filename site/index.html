08 · THE ADHERENCE BOARD — TASKS GRADED ON HOW THEY RAN

The Polaris Task Shell is a frame for running a software task: the spec and the rubric are registered before work begins; the work runs inside the shell; every run is receipted; and adherence to the spec is graded separately from whether the task succeeded. The two grades are independent by design — a task can succeed with poor adherence, and a task can fail with full adherence — and the board carries both, because adherence is the grade a demonstration cannot show.

gradeR scores adherence from the task's own record, on six criteria: the spec pre-registered before the first run; every run receipted, with starting state and output; grades read from checker output and artifacts; corrections appended at equal prominence, naming the entry corrected; unbuilt and unmeasured items labeled as such on the record; the task's absolute gates checked and reported, pass or fail.

First entries, 2026-11-19 — the estate's own tasks, graded first. Each entry states what was claimed up front, what the evidence shows, and the grade.

Entries 7–10, added 2026-11-21 — the IMBUUID buildout generations, run under the Polaris Task Shell (SOM-DOC-10882) and graded on its nine criteria: the six above plus the loop's three contamination questions — the recipe followed, not improvised; the spec uncontaminated by the run's own output; the promotion rule applied as written. Adherence and success are graded separately, as the shell requires, and PARTIALs print at the same size as PASSes.
